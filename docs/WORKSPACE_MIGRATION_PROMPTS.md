# Промпты для переноса AI Dev Team на другой компьютер

Эти промпты предназначены для Windows и Codex. Отправляй их по порядку в отдельных сообщениях. Перед началом замени URL репозиториев только при необходимости.

## Общие условия

- Домашний каталог обозначается как `~` или `$HOME`.
- AI Dev Team должен находиться в `~/codex-workspace`.
- Рабочие проекты должны находиться в `~/codex-workspace/projects/<project>`.
- Каждый каталог верхнего уровня в `projects/` должен быть отдельным Git-репозиторием.
- Корневой репозиторий `codex-workspace` не должен отслеживать содержимое `projects/`.
- Не передавай в чат и не коммить токены, API-ключи, пароли или содержимое файлов окружения.
- Не удаляй исходные каталоги, пока копия не проверена по количеству файлов, размеру и SHA-256.

## Промпт 1 — инвентаризация

```text
Работаем на Windows. Сначала выполни только read-only инвентаризацию.

1. Найди существующие каталоги codex-workspace, projects и прежний web-root вроде C:\MAMP\htdocs.
2. Найди все независимые Git-репозитории, включая вложенные.
3. Для каждого репозитория покажи текущую ветку, origin, незакоммиченные изменения и наличие вложенных репозиториев.
4. Найди глобальные файлы Codex в ~/.codex: AGENTS.md, AGENTS.override.md, config.toml, hooks.json, agents, rules и связанные skills.
5. Не выводи значения секретов из config.toml или переменных окружения.
6. Составь план переноса в ~/codex-workspace, но пока ничего не перемещай, не удаляй и не публикуй.
```

## Промпт 2 — безопасный перенос

```text
Теперь выполни безопасный перенос.

Целевая структура:
- ~/codex-workspace — репозиторий AI Dev Team;
- ~/codex-workspace/presets — шаблоны проектов;
- ~/codex-workspace/projects — только отдельные рабочие Git-репозитории.

Если codex-workspace ещё не существует, клонируй:
https://github.com/ZabulaAleksey/codex-workspace.git

Если на компьютере есть старые проекты в ~/projects или C:\MAMP\htdocs, перенеси каждый проект в ~/codex-workspace/projects/<project>.

Перед удалением каждого источника:
1. скопируй данные;
2. сравни число файлов и общий размер;
3. сравни SHA-256 всех файлов;
4. проверь Git status и remotes в копии;
5. только после нулевого числа расхождений удали старый источник.

Не объединяй Git-истории разных проектов. Не добавляй projects/ в индекс внешнего репозитория codex-workspace.
```

## Промпт 3 — настройка глобального контекста

```text
Настрой AI Dev Team из ~/codex-workspace.

1. Прочитай ~/codex-workspace/AGENTS.md и install-global.ps1.
2. Сравни ~/.codex/AGENTS.md с global/codex/AGENTS.md.
3. Глобальный AGENTS.md должен быть коротким мостом к ~/codex-workspace/AGENTS.md, без дублирования всей библиотеки правил.
4. Запусти install-global.ps1 без -Force, чтобы не перезаписать существующий config.toml.
5. Объедини только необходимые несекретные параметры из global/codex/config.windows.recommended.toml с ~/.codex/config.toml.
6. Сохрани все существующие пользовательские MCP, плагины, модель и секреты.
7. Добавь trust_level = "trusted" для ~/codex-workspace и каждого активного проекта.
8. Проверь TOML-парсером config.toml и все пользовательские agent-файлы.
9. Выполни codex mcp list, но не печатай API-ключи.
10. Сообщи, какие hooks требуют ручного подтверждения через /hooks.
```

## Промпт 4 — проверка конфликтов контекста

```text
Проверь и устрани конфликты контекста Codex.

1. Проверь цепочку ~/.codex/AGENTS.md → ~/codex-workspace/AGENTS.md → локальный AGENTS.md проекта.
2. Убедись, что более локальные правила имеют приоритет и не дублируют глобальные.
3. Проверь отсутствие AGENTS.override.md, который неожиданно скрывает обычный AGENTS.md.
4. Проверь размер объединяемых AGENTS.md относительно project_doc_max_bytes.
5. Для каждого проекта создай минимальный локальный AGENTS.md только с проектными особенностями и ссылкой на AI Dev Team.
6. Проверь project-local .codex/config.toml, hooks и rules; они должны загружаться только для trusted-проектов.
7. Найди устаревшие абсолютные пути и замени переносимыми путями от ~.
8. Не загружай все rules, SPEC и LEARNING_LOG в контекст одновременно.
```

## Промпт 5 — Git-проверка и публикация

```text
Подготовь и опубликуй изменения во всех затронутых репозиториях.

Для каждого репозитория отдельно:
1. проверь git status, diff, diff --check, ignored-файлы, секреты и крупные файлы;
2. убедись, что внешний codex-workspace не отслеживает projects/;
3. выполни релевантные синтаксические и конфигурационные проверки;
4. создай отдельный Conventional Commit в рабочей ветке;
5. получи свежий origin;
6. проверь конфликт с главной веткой;
7. выполни обычное слияние без force push;
8. отправь главную ветку в соответствующий origin;
9. сравни локальный HEAD с origin/main.

Не публикуй вложенный upstream-репозиторий вроде ffmpeg, если в нём нет наших изменений и отдельного явного разрешения.
```

## Промпт 6 — аудит диска без удаления

```text
Проведи read-only аудит C:\Users и особенно моего домашнего каталога.

1. Покажи размер каталогов верхнего уровня и самые крупные файлы.
2. Отдельно найди кэши, временные каталоги, старые установщики, crash-dumps, логи, дубликаты архивов и остатки прежних рабочих каталогов.
3. Не открывай и не показывай содержимое личных документов, писем, браузерных профилей, токенов и файлов окружения.
4. Раздели кандидатов на:
   - обычно безопасно очистить;
   - можно удалить только после проверки приложения;
   - не трогать.
5. Для каждого кандидата укажи путь, размер, назначение, риск и способ восстановления.
6. Ничего не удаляй без отдельного подтверждения с точным перечнем путей.
```

## Финальная проверка

После завершения попроси Codex подтвердить:

- `C:\MAMP\htdocs` пуст или отсутствует;
- `~/projects` пуст или отсутствует;
- `~/codex-workspace` является отдельным репозиторием;
- каждый каталог в `~/codex-workspace/projects` является отдельным репозиторием;
- `projects/` игнорируется внешним Git;
- глобальный и проектные контексты не превышают установленный лимит;
- локальные главные ветки совпадают с соответствующими `origin/main`.
