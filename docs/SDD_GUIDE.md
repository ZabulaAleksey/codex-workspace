# SDD в AI Dev Team

## Источник истины

SPEC описывает стабильное наблюдаемое поведение продукта. Prompt описывает одноразовую работу агента. Код реализует SPEC, а тесты подтверждают соответствие.

## Структура проекта

```text
AGENTS.md
docs/
  ARCHITECTURE.md
  DESIGN.md
  DECISIONS.md
  AI_STATUS.md
  ROADMAP.md
  SECURITY.md        # при наличии рисков безопасности
specs/
  README.md
  system.spec.md
  features/
    <feature>.spec.md
```

`AI_STATUS.md` уже является снимком текущего состояния, поэтому отдельный `PROJECT_SNAPSHOT.md` не нужен.

## Когда нужна SPEC

- `SIMPLE`: не создаётся автоматически; существующая SPEC обновляется при изменении существенного поведения.
- `STANDARD`: обязательна для новой функциональности.
- `COMPLEX`: полная SPEC, архитектурная проверка, анализ рисков и строгая validation обязательны.
- Prototype: допускается краткая экспериментальная SPEC с явными допущениями.

## Трассировка

Используй стабильные идентификаторы `FR-###`, `NFR-###`, `SEC-###`, `PERF-###` и `AC-###`. В тесте или таблице соответствия указывай, какие требования он покрывает.

## Контекст

Hook загружает только `specs/README.md` и `specs/system.spec.md`. Конкретную feature-SPEC агент выбирает по текущей задаче. Это предотвращает загрузку всех спецификаций.
