## Приоритет проектных инструкций

Этот файл содержит глобальные правила работы Codex.

Если в рабочем пространстве или проекте присутствуют дополнительные инструкции AI Dev Team, например:

`~/codex-workspace/AGENTS.md`

то перед выполнением задачи необходимо прочитать их.

### Приоритет правил

При конфликте инструкций используй следующий порядок приоритета:

1. Проектный / наиболее локальный `AGENTS.md`
2. Правила AI Dev Team
3. Этот глобальный `AGENTS.md`

Более специфичные инструкции имеют приоритет над общими.

Не дублируй:
- subagents;
- hooks;
- MCP;
- skills;
- Git workflow;
- архитектурные правила;
- правила тестирования,

если они уже определены AI Dev Team или локальным проектом.

### КАРКАС проекта

Запросы «создай КАРКАС» и «сделай АВТОМАТИЗАЦИЮ КОНТЕКСТА» означают проектирование или настройку project-specific living contract поверх существующей AI Dev Team, а не немедленную реализацию продукта. Если доступна рабочая область `~/codex-workspace`, прочитай её `docs/PROJECT_FRAMEWORK.md`, `docs/CONTEXT_POLICY.md` и `docs/CONTEXT_COMPATIBILITY.md`, затем выполни inspect → gap analysis → minimal project delta.

### Язык контекста

Новый и обновляемый проектный контекст по умолчанию оформляй на русском языке. Сохраняй без перевода программные идентификаторы, API, команды, пути, имена технологий и машинные ключи. Используй другой основной язык только по прямому требованию пользователя или внешнего контракта проекта.
