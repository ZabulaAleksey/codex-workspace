## Приоритет проектных инструкций

Этот файл содержит глобальные правила работы Codex.

Если в рабочем пространстве или проекте присутствуют дополнительные инструкции AI Dev Team, например:

`~/codex-workspace/AGENTS.md`

то перед выполнением задачи необходимо прочитать их.

### Приоритет правил

При конфликте инструкций используй следующий порядок приоритета:

1. Проектный / наиболее локальный `AGENTS.md`
2. Правила AI Dev Team
3. Этот глобальный `AGENTS.md`

Более специфичные инструкции имеют приоритет над общими.

Не дублируй:
- subagents;
- hooks;
- MCP;
- skills;
- Git workflow;
- архитектурные правила;
- правила тестирования,

если они уже определены AI Dev Team или локальным проектом.

### КАРКАС проекта

Запросы «создай КАРКАС» и «сделай АВТОМАТИЗАЦИЮ КОНТЕКСТА» означают проектирование или настройку project-specific living contract поверх существующей AI Dev Team, а не немедленную реализацию продукта. Если доступна рабочая область `~/codex-workspace`, прочитай её `~/codex-workspace/docs/PROJECT_FRAMEWORK.md`, `~/codex-workspace/docs/CONTEXT_POLICY.md` и `~/codex-workspace/docs/CONTEXT_COMPATIBILITY.md`, затем выполни inspect → gap analysis → minimal project delta.

### Язык контекста

Новый и обновляемый проектный контекст по умолчанию оформляй на русском языке. Сохраняй без перевода программные идентификаторы, API, команды, пути, имена технологий и машинные ключи. Используй другой основной язык только по прямому требованию пользователя или внешнего контракта проекта.

## Маршрутизация моделей и субагентов

Главный агент является оркестратором. Не выполняй всю работу на самой мощной модели, если задача может быть безопасно делегирована специализированному субагенту.

### Базовая маршрутизация

Используй Luna для:

- поиска файлов и символов;
- исследования репозитория;
- чтения документации;
- классификации и извлечения информации;
- простых преобразований;
- запуска и первичного анализа тестов;
- других хорошо определённых повторяемых операций.

Используй Terra для:

- обычной реализации;
- frontend/backend разработки;
- локального рефакторинга;
- обычного debugging;
- написания тестов;
- исправления хорошо локализованных ошибок.

Используй Sol для:

- архитектуры;
- неоднозначных задач;
- сложного debugging;
- security-critical задач;
- concurrency и race conditions;
- миграций с риском потери данных;
- важных публичных API;
- решений с существенными долгосрочными последствиями.

### Эскалация

Используй последовательность `Luna → Terra → Sol`.

Повышай уровень модели, если более лёгкий агент не смог решить задачу, требования оказались неоднозначными, тесты продолжают падать после разумной попытки исправления, обнаружено влияние на архитектуру, возник риск безопасности или потери данных либо требуются существенные trade-offs. Не повышай модель только из-за размера файла или количества строк.

### Делегирование

Для задачи, которую разумно разделить на независимые части, используй субагентов вместо последовательного выполнения всей работы главным агентом.

После завершения субагентов главный агент обязан собрать результаты, устранить противоречия, проверить соответствие SPEC/ARCHITECTURE и обеспечить выполнение Definition of Done и обязательных тестов. Субагент не имеет права ослаблять эти требования ради скорости.
