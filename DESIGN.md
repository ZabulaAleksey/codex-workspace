# Дизайн Rozmova

> Статус: начальный визуальный baseline (`v0.1`).
>
> Основание: предоставленный desktop-референс страницы поиска специалистов, 1800 × 822 px.
>
> Точность: размеры и цвета ниже восстановлены визуально и подлежат уточнению по мере развития проекта.

## 1. Назначение документа

Этот файл фиксирует текущий визуальный язык интерфейса, чтобы новые экраны и компоненты выглядели как части одного продукта. Пока референс показывает только desktop-страницу каталога, поэтому наблюдаемые решения отделены от гипотез о поведении на других экранах.

Если будущий макет противоречит этому документу, сначала уточняется дизайн, затем обновляется `DESIGN.md`.

## 2. Общее впечатление

Интерфейс должен ощущаться:

- спокойным, доброжелательным и безопасным;
- простым, без визуального шума;
- современным, но не «технологичным ради технологии»;
- светлым, с большим количеством воздуха;
- ориентированным на быстрое сравнение специалистов и запись на сессию.

Основной акцент — яркий сине-фиолетовый цвет. Он используется для активной навигации, ссылок, контурных кнопок и главного действия. Дополнительные зелёный, розовый и оранжевый обозначают статус, особую квалификацию и срочную доступность.

## 3. Структура desktop-экрана

### 3.1. Общий layout

- Минимальная подтверждённая ширина референса: `1800 px`.
- Слева находится фиксированная белая боковая панель шириной около `277 px`.
- Справа — светло-серая рабочая область с едва заметным декоративным паттерном.
- Основная лента имеет ширину около `960 px` и располагается ближе к центру рабочей области.
- Карточки идут одной колонкой с вертикальным интервалом около `20 px`.
- Контент страницы прокручивается вертикально; поведение боковой панели при прокрутке пока не подтверждено.

```text
┌────────────────────┬───────────────────────────────────────────────┐
│                    │                                               │
│  Боковая панель    │         Лента карточек специалистов           │
│  ≈ 277 px          │         ≈ 960 px                              │
│                    │                                               │
│  Логотип           │  ┌─────────────────────────────────────────┐  │
│  Навигация         │  │ Фото │ Информация, метрики и действия   │  │
│  Приглашение       │  └─────────────────────────────────────────┘  │
│  Профиль           │                                               │
│  Поддержка         │  ┌─────────────────────────────────────────┐  │
│                    │  │ Фото │ Информация, метрики и действия   │  │
└────────────────────┴──┴─────────────────────────────────────────┴──┘
```

### 3.2. Боковая панель

- Белый фон без тени; граница с рабочей областью создаётся разницей фонов.
- Внутренние горизонтальные отступы: примерно `27–34 px`.
- Логотип расположен сверху с большим нижним отступом.
- Основная навигация состоит из иконки и подписи.
- Высота активного пункта: около `56 px`; скругление: около `14 px`.
- Активный пункт получает очень светлый синий фон и синий текст с иконкой.
- Неактивные пункты используют нейтральный серый цвет.
- Группы навигации разделяются тонкой горизонтальной линией.
- Нижняя часть содержит приглашение близких с QR-кодом, профиль пользователя и ссылку на поддержку.

Подтверждённые пункты навигации:

1. Пошук — активный пункт.
2. Моя терапія.
3. Чати.
4. Нотатки.
5. Запросити близьких.
6. Мій профіль.
7. Служба підтримки.

## 4. Карточка специалиста

Карточка — основной повторяемый компонент каталога.

### 4.1. Контейнер

- Белый фон.
- Тонкая нейтральная граница, ориентировочно `1 px`.
- Скругление около `20 px`.
- Без заметной тени в обычном состоянии.
- Внутренний отступ около `30 px`.
- Desktop-компоновка: фотография слева, информация справа.
- Ориентировочная высота показанной карточки: `345 px`.

### 4.2. Фото и видео

- Медиа имеет квадратное соотношение `1:1`, около `266 × 266 px`.
- Скругление изображения: около `14 px`.
- Фото заполняет контейнер через `object-fit: cover` без деформации.
- В левом нижнем углу находится круглая белая кнопка воспроизведения.
- В правом нижнем углу находится зелёный индикатор доступности.
- Индикатор имеет тонкую белую обводку, чтобы не теряться на фото.

### 4.3. Информационная часть

Порядок информации сверху вниз:

1. Имя специалиста.
2. Необязательный бейдж квалификации и иконка с пояснением.
3. Опыт работы.
4. Роль или специализация.
5. Основные метрики: цена, отзывы, количество сессий.
6. Дополнительные метрики: недавние записи и количество текущих просмотров.
7. Краткое описание специалиста, ограниченное по высоте.
8. Подпись «Найближчий час:».
9. Ближайший слот и действия.

Имя и опыт визуально важнее специализации. Метрики компактны, читаются слева направо и сопровождаются цветными иконками. Длинное описание обрезается многоточием; карточка не должна бесконтрольно расти из-за текста.

### 4.4. Действия

- Ближайший слот показан как светлый компактный badge.
- Срочный слот дополнительно получает оранжевую молнию.
- Кнопка чата квадратная, контурная, примерно `56 × 56 px`.
- Главное действие «Переглянути доступність» — залитая синяя кнопка высотой около `55 px`.
- У кнопок крупное скругление, ориентировочно `14–16 px`.
- Иконка календаря и текст главной кнопки белые.
- Действия собраны в одну горизонтальную строку и визуально выровнены по высоте.

## 5. Цветовая система

Значения ориентировочные. Перед реализацией pixel-perfect версии их следует снять из исходного макета или уточнить инструментально.

| Token | Ориентир | Назначение |
|---|---:|---|
| `color.brand.primary` | `#4767F5` | Главное действие, активный пункт, ссылки, иконки |
| `color.brand.primary-hover` | `#3858E8` | Предлагаемое состояние наведения |
| `color.brand.soft` | `#F4F6FF` | Активная навигация, фон временного слота |
| `color.text.primary` | `#090909` | Заголовки и основной текст |
| `color.text.secondary` | `#626262` | Специализация и вторичные подписи |
| `color.surface.primary` | `#FFFFFF` | Карточки и боковая панель |
| `color.surface.page` | `#FAFAFA` | Фон рабочей области |
| `color.border.default` | `#E4E4E4` | Границы карточек и разделители |
| `color.status.success` | `#13B97A` | Онлайн-статус, положительные отзывы |
| `color.status.attention` | `#FFAC32` | Ближайшая или срочная доступность |
| `color.status.expert` | `#FF4D8D` | Бейдж особой квалификации |
| `color.icon.muted` | `#707070` | Неактивные иконки навигации |

Цвет не должен быть единственным носителем смысла: статус всегда дополняется иконкой, текстом или доступным названием.

## 6. Типографика

Точное семейство шрифта по изображению не подтверждено. До появления исходного макета использовать нейтральный современный sans-serif:

```css
font-family: Inter, Arial, sans-serif;
```

Ориентировочная шкала:

| Роль | Размер | Начертание | Межстрочный интервал |
|---|---:|---:|---:|
| Логотип | `34 px` | `400–500` | `1.1` |
| Имя специалиста | `24 px` | `700` | `1.2` |
| Основной текст | `18–19 px` | `400` | `1.35` |
| Опыт / важная подпись | `18 px` | `600` | `1.3` |
| Навигация | `20–21 px` | `400–500` | `1.25` |
| Кнопка | `18 px` | `600–700` | `1.2` |
| Вспомогательный текст | `14–16 px` | `400–600` | `1.3` |

Правила:

- основной текст выравнивается по левому краю;
- заголовки и подписи используют обычный регистр, без капса;
- жирность применяется точечно для имени, опыта, цены и действий;
- текст не должен становиться плотнее референса ради размещения большего объёма данных.

## 7. Иконки и декоративная графика

- Иконки линейные, с округлыми окончаниями штрихов.
- Рекомендуемый визуальный размер в навигации: `24–28 px`.
- Активные и смысловые иконки окрашиваются контекстно; декоративные остаются нейтральными.
- Логотип состоит из синего скруглённого знака и чёрного wordmark `Rozmova`.
- Паттерн рабочей области собирается из тематических outline-иконок: сообщения, сердце, график, часы, заметки и другие.
- Паттерн должен быть почти незаметным: очень низкий контраст, без конкуренции с карточками.

Не смешивать разные стили иконок — filled, outline и duotone — внутри одной функциональной группы.

## 8. Скругления, границы и интервалы

Рекомендуемые базовые токены, выведенные из референса:

```text
radius.small   = 8 px
radius.medium  = 14 px
radius.large   = 20 px

space.1 = 4 px
space.2 = 8 px
space.3 = 12 px
space.4 = 16 px
space.5 = 20 px
space.6 = 24 px
space.7 = 30 px
space.8 = 40 px
```

- Использовать тонкие границы вместо тяжёлых теней.
- Внутри карточки придерживаться плотного вертикального ритма `6–12 px` между связанными строками.
- Между смысловыми блоками оставлять `16–24 px`.
- Крупные поверхности и интерактивные элементы имеют заметные, но не капсульные скругления.

## 9. Состояния компонентов

В референсе показаны не все состояния. Для целостной реализации предусмотреть:

- `default` — как на референсе;
- `hover` — лёгкое усиление границы или фона без скачка размеров;
- `focus-visible` — контрастное фокус-кольцо вокруг всего интерактивного элемента;
- `active` — небольшое затемнение основного цвета;
- `disabled` — сниженный контраст с сохранением читаемости;
- `loading` — skeleton, повторяющий геометрию карточки;
- `empty` — спокойное объяснение и одно следующее действие;
- `error` — текстовое сообщение с возможностью повторить загрузку.

Карточка не должна выглядеть кликабельной целиком, если переход выполняется только отдельной кнопкой. Если вся карточка становится ссылкой, вложенные кнопки обязаны оставаться самостоятельными доступными действиями.

## 10. Адаптивность

Мобильный и tablet-варианты в исходном референсе отсутствуют. Следующие пункты являются рабочими гипотезами, а не подтверждённым дизайном:

- на средней ширине боковая панель может сворачиваться до панели иконок;
- на мобильном экране навигация должна перейти в отдельное меню или нижнюю панель;
- карточка должна перестраиваться в одну колонку: медиа, информация, слот, действия;
- главное действие на мобильном занимает всю доступную ширину;
- метрики переносятся целыми смысловыми группами, а не разрываются посередине;
- декоративный паттерн можно упростить или скрыть для снижения визуального шума.

До появления мобильного референса не считать конкретные breakpoint-значения частью дизайн-контракта.

## 11. Доступность

- Минимальная область нажатия: `44 × 44 px`.
- Все иконки-кнопки получают доступное текстовое название.
- Видео не запускается автоматически со звуком.
- Фотографии специалистов имеют содержательный `alt`; декоративный фон скрыт от скринридеров.
- Видимый `focus-visible` обязателен для навигации, слотов и кнопок.
- Контраст обычного текста и интерактивных состояний проверяется по WCAG AA.
- Обрезанное описание должно иметь доступ к полной версии на странице специалиста; tooltip не используется для длинного основного текста.

## 12. Контент и локализация

- Язык показанного интерфейса — украинский.
- Компоненты должны выдерживать более длинные имена, специализации и локализованные подписи.
- Денежные значения отображаются с валютой: `3000 грн`.
- Дата и время оформляются в локальном формате: `17 серп, 11:00`.
- Числа и подписи не склеиваются при переносе строки.
- Тон текста — человечный, ясный и поддерживающий, без канцелярита.

## 13. Критерии визуального соответствия

Экран считается согласованным с этим baseline, если:

- сохранена двухчастная desktop-композиция с белой боковой панелью;
- контент собран в одну читаемую колонку карточек;
- карточки белые, с тонкой границей, крупным скруглением и без тяжёлой тени;
- фото остаётся главным визуальным якорем карточки;
- имя, опыт, метрики, описание и ближайший слот имеют ясную иерархию;
- главное действие выделено синим, а вторичное показано контуром;
- фон и декоративный паттерн не снижают читаемость;
- интерфейс сохраняет просторный, спокойный характер референса.

## 14. Что ещё нужно уточнить

- точное семейство и файлы шрифтов;
- исходные значения цветов и размеров из дизайн-макета;
- правила sticky-поведения боковой панели;
- hover, focus, loading, empty и error-состояния;
- поведение видеопревью;
- значение зелёной точки: онлайн, доступен сейчас или другой статус;
- логика бейджа `Суперфахівець` и поясняющей иконки;
- tablet- и mobile-компоновка;
- максимальная длина описания и точное правило обрезки;
- является ли фоновый паттерн обязательным бренд-элементом.
