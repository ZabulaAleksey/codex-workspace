# Проверка соответствия SPEC

## Цель

Подтвердить, что реализация и тесты соответствуют актуальным требованиям, а не только успешно собираются.

## Порядок

1. Перечисли затронутые идентификаторы требований и критериев приёмки.
2. Для каждого требования найди реализацию и способ проверки.
3. Выполни связанные unit, integration или E2E-тесты.
4. Для `PERF-###` используй воспроизводимый benchmark.
5. Для `SEC-###` проверь границы доверия и негативные сценарии.
6. Проверь ошибки, альтернативные потоки и edge cases.
7. Зафиксируй непроверенные требования и причину.

## Результат

Отчёт должен разделять:

- подтверждённое соответствие;
- частичное соответствие;
- расхождение реализации и SPEC;
- устаревшую или неоднозначную SPEC;
- отсутствующие автоматические проверки.

Нельзя исправлять расхождение только ослаблением корректного теста. Сначала определи, ошибочны ли SPEC, тест или реализация.
