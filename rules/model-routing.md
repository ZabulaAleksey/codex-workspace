# Model Routing Policy

## Базовое правило

По умолчанию используй **GPT-5.3-Codex-Spark** для задач разработки небольшого и среднего масштаба.

Не используй более тяжёлую Codex-модель только потому, что она доступна. Выбирай её тогда, когда сложность, длительность или объём контекста действительно это оправдывают.

## Использовать Spark по умолчанию

Spark предпочтителен для:

- исправления локальных багов;
- небольших и средних feature-задач;
- UI/CSS/UX-изменений;
- изменений отдельных компонентов, функций или модулей;
- небольшого рефакторинга;
- написания и исправления тестов;
- документации;
- изменения SPEC/AI_PLAN/AI_STATUS;
- project-overlay / КАРКАС-операций небольшого масштаба;
- локального анализа ошибки;
- dependency/config changes;
- небольших API-изменений;
- code review и устранения конкретных замечаний;
- задач, которые можно выполнить с ограниченным набором файлов и сравнительно небольшим контекстом.

## Использовать основной Codex

Переключайся с Spark на более мощную Codex-модель, если задача содержит хотя бы один существенный признак:

- крупная архитектурная переработка;
- изменение нескольких подсистем одновременно;
- большой или неоднозначный SPEC;
- длительная автономная реализация полноценного этапа;
- массовая миграция;
- сложный debugging без очевидной локализации проблемы;
- security-critical изменение;
- сложные конкурентные/realtime/distributed алгоритмы;
- необходимость анализировать значительную часть большого repository;
- сложный cross-project refactoring;
- задача требует большого количества последовательных решений и повторных проверок;
- Spark уже попытался решить задачу, но качество или глубина оказались недостаточными.

## Принцип эскалации

Используй следующую стратегию:

`Spark → выполнить задачу, если она локальна и понятна → основной Codex только при необходимости`.

Не используй стратегию:

`самая мощная модель → для любой задачи`.

## Проверки

Выбор Spark не отменяет Definition of Done, тесты, review, security rules, Git workflow и остальные quality gates проекта.

Если Spark по умолчанию не запускает необходимые проверки автоматически, явно запусти проверки, требуемые SPEC, AGENTS.md и Definition of Done.

## Если модель нельзя выбрать автоматически

Если текущая среда не позволяет агенту самостоятельно выбрать или сменить модель:

1. Определи рекомендуемый класс модели до начала существенной работы.
2. Если задача подходит для Spark — пометь её как `SPARK_PREFERRED`.
3. Если задача требует основной Codex-модели — пометь её как `FRONTIER_REQUIRED`.
4. Не усложняй небольшой task только ради оправдания использования более мощной модели.

## Цель

Максимально использовать отдельный ресурс и высокую скорость Codex-Spark для повседневной разработки, сохраняя основной Codex для задач, где его дополнительное reasoning и long-horizon agentic выполнение действительно дают преимущество.
